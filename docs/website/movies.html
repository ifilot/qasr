Camera orbits & reaction movies

Orbit a camera around a structure, or play a sequence of geometries with one fixed view. Render frames directly into an MP4 using optional shared FFmpeg libraries.

Enable movie support when building

sudo apt install libavcodec-dev libavformat-dev libavutil-dev libswscale-dev
cmake -S . -B build-movies -DCMAKE_BUILD_TYPE=Release -DENABLE_FFMPEG=ON
cmake --build build-movies --parallel
build-movies/qasr --build-info

Look for "ffmpeg":true. The option defaults to OFF; an image-only build has no FFmpeg dependencies and rejects movie requests explicitly. Enabled builds require the shared libraries at runtime. QASR calls those libraries directly: no separate ffmpeg process or PNG sequence is needed.

For the test suite’s independent movie decoding and timing checks, also install the ffmpeg package, which supplies ffmpeg and ffprobe. They are optional validation tools and are not called by the renderer.

Orbit around a complete zeolite cage

Extract the example kit into examples/, then run from the parent directory:

build-movies/qasr examples/cage.xyz \
  --config examples/zeolite-faces.json --no-user-config \
  --movie orbit --movie-frames 120 --movie-fps 24 \
  --movie-axis 0,0,1 --movie-angle 360 -o orbit.mp4

This produces five seconds of video. The camera starts at the recipe’s view, orbits around the displayed structure’s center, and keeps one zoom throughout. The entire scene fits the full orbit. A complete revolution omits the duplicate final pose for smooth looping.

Choose any nonzero world-space axis. Negative angles reverse the direction. Use --cell off when cell or vacuum extents would make the structure too small.

Play a reaction coordinate with a fixed camera

build-movies/qasr examples/reaction.xyz \
  --config examples/reaction.json --no-user-config \
  --movie trajectory --movie-fps 24 --movie-interpolate 3 \
  --report reaction-report.json -o reaction.mp4

Download the trajectory and recipe individually, or use the kit. The supplied H + H2 exchange path contains 15 synthetic geometries. It is an illustrative animation, without calculated energies, forces or a physical time scale. Stable source-index colors make the exchanging atoms easy to follow.

The camera’s direction, position and zoom stay fixed. A streaming prepass fits every source and interpolated pose, so moving atoms do not cause zooming or recentering. Connectivity is rebuilt from the configured bond cutoffs for each output frame.

Trajectory mode accepts multi-frame XYZ, Extended XYZ, OUTCAR and XML ionic snapshots. It uses all source frames, with the same atom count, order, element identities and periodic axes throughout. Lattice vectors may vary. XML initialpos and duplicate finalpos structures are not extra playback frames.

Interpolation smooths a supplied path

Three inserted geometries per interval turn 15 snapshots into 57 frames, played at 24 fps. Positions and cell vectors interpolate linearly. QASR does not calculate reaction chemistry, match atom identities, infer dynamics or unwrap periodic boundaries. For a continuous molecular path, cell-free XYZ is convenient.

Movie controls

ControlValues and defaultUse
--movieorbit, trajectoryChoose camera motion or geometry playback.
--movie-fps1–120; default 30Set the playback frame rate.
--movie-frames2–100000; default 120Number of orbit frames.
--movie-axisX,Y,Z; default 0,0,1World Cartesian axis for an orbit.
--movie-angleNonzero −3600 to 3600 degrees; default 360Orbit angle; partial turns include both endpoint poses.
--movie-interpolate0–1000; default 0Inserted trajectory frames per source interval.
--movie-codecauto, h264, mpeg4; default autoAuto prefers libx264 H.264, falling back to native MPEG-4 Part 2.

MP4 requires an opaque background and even width/height, each at most 4096 pixels, subject to the allocation budget. Encoding uses YUV 4:2:0 color, so it is not lossless RGB. Explicit H.264 requires libx264 in the linked FFmpeg build. Movies use the Z-buffer renderer. PNG encoder controls apply to still images.

Orbit mode can select its source geometry with --frame. Trajectory mode uses all snapshots and rejects frame selection and orbit-only controls.

Reuse settings in jobs and batches

{
  "input": "reaction.xyz",
  "output": "reaction.mp4",
  "no_user_config": true,
  "movie": {"mode": "trajectory", "fps": 24, "interpolate": 3},
  "config": {
    "image": {"width": 640, "height": 360},
    "camera": {"view": [0, 0, 1], "up": [0, 1, 0]},
    "overlays": {"cell": false}
  }
}

Movie controls belong to the invocation’s movie object, outside the rendering config. Save this beside the trajectory and run qasr --job movie-job.json. Batch render requests accept the same job structure. See the job schema and batch guide.

--report records the actual encoder, frame count, duration, dimensions, hashes, camera settings and fit/render/encode timings. --benchmark-stages prints timing totals. Encoding, flushing, trailer writing and close must all succeed before the destination is replaced. Cancellation removes unfinished movie data. The separately requested JSON report is an independent file commit.

Keep the input unchanged during rendering. Only the necessary snapshots, scene and encoding workspace are retained in memory. The movie is streamed into a temporary local file, then committed on success.
