RENDER MORE, WAIT LESS

Batch rendering & speed

Render several views or structures in one process. Reuse geometry where possible, choose how many CPU threads to use, and measure the time spent on each step.

Choose the workflow that fits

Your taskStart withWhy
One imageqasr INPUT -o image.pngA single command with an optional JSON recipe.
Several views of one structureqasr --batchThe process can retain the parsed structure and scene between requests.
Many independent structuresSeveral batch workersRun workers from your own script; assign each a distinct output path and a share of the available CPUs.

Batch requests run sequentially within one worker. Each individual render can use several CPU threads when the build includes OpenMP. Check the available features with qasr --build-info.

Try a complete batch

Save worker-requests.jsonl and CONTCAR.co in the same directory. Open a terminal in that directory and run:

qasr --batch < worker-requests.jsonl > responses.jsonl

This creates worker-top.png and worker-oblique.png, then returns cache statistics. Each input line is a separate JSON request; each response is one JSON line. Images are written to files.

A minimal request

{"id":"top-view","op":"render","job":{"input":"CONTCAR.co","output":"top.png","config":{"camera":{"view":"top"},"image":{"width":768,"height":768}}}}

Use a printable ID to match a response to its request. Read ok in each response: the worker can report an unsuccessful request and continue with the next one. Paths are relative to the directory where you start the worker. Create output directories beforehand.

Keep a batch reproducible

The worker skips automatic personal preferences. Put the required settings in each request’s job.config. The worker schema describes the complete request format.

Reuse input and scene data

qasr --batch --cache-mib 128 --max-jobs 100 < requests.jsonl

--cache-mib bounds retained input and scene data; its default is 64 MiB and its range is 0–512 MiB. Zero disables caching. This limit does not include all memory used while rendering an image. --max-jobs stops the worker after a chosen number of requests; otherwise it runs until the input ends.

Changing the camera or output size can reuse a scene. Changing bond connectivity, repetition or atom geometry requires an appropriate new scene. Source content is checked before reuse. Reports expose source_hit and scene_hit; a cache hit does not skip rendering or output encoding.

OperationExample input lineResult
Validate a job{"id":"check","op":"validate","job":{"input":"CONTCAR.co"}}Check input and settings without writing an image.
Inspect the cache{"id":"memory","op":"stats"}Read counters and retained memory.
Release cached data{"id":"release","op":"clear_cache"}Clear retained input and scene data.

Start the command with --batch; only --cache-mib and --max-jobs follow it. Put per-render settings inside the JSON requests.

Choose CPU threads

qasr CONTCAR --threads 4 --width 1200 --height 900 -o structure.png

--threads auto is the default. It selects one worker for small images and up to eight for images at least 512 × 512 pixels, subject to environment limits. An explicit count accepts 1–256. Serial builds support one thread; multiple threads require OpenMP.

For batch requests, set job.threads, for example "threads":4. When running several processes, divide the available cores between them. More threads can add overhead on small images, so compare the settings on your own workload.

Balance image quality and turnaround

ControlPractical use
--width, --heightStart at 768 pixels for a preview; increase for the final figure. Doubling both dimensions produces four times as many output pixels.
--aa native|2x|4x|adaptiveNative is useful for quick checks; 2× is the default; 4× provides more samples. Adaptive selectively refines supported scenes and falls back to full sampling when required.
--png-compression 1A useful compact PNG starting point. Compression changes file size and encoding time while preserving pixels with libpng/libdeflate.
--expand-xy, --repeatInclude the neighboring cells your figure needs. Larger patches add atoms and bonds to process.

Measure your workflow

qasr CONTCAR --width 1200 --height 900 --threads 4 \
  --benchmark-stages --report render-report.json -o structure.png

--benchmark-stages writes stage timings to stderr. --report saves settings, counts, input/output hashes and timings as JSON. Compare the same structure, view, image size, sampling and output format. Run each setting several times; storage and background CPU activity can affect the result.

Batch response timings describe individual requests. Measure the whole process separately when startup and total batch completion time matter. The repository includes benchmark tools and raw results for more detailed development work.
